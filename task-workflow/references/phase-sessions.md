# 多 session 阶段

主控统一选择阶段、保存全局记录、交接和重试；每个 phase 主 agent 可以处理职责内讨论并展示详细结果，但不得扩大范围或绕过主控。一个任务同一时刻只启动一个 phase；phase 内部可按依赖和后端容量使用子 agent。

| 阶段 | 主 agent 与子 agent 职责 | 完成标准 |
| --- | --- | --- |
| discuss | 调研代码、历史和材料，按材料需要最多使用代码与非代码两类子 agent，无相应材料不为凑人数创建；区分事实、推断与未知项 | 交付需求基线或排查结论；要求根因/复现而未证明时不报成功 |
| plan | plan 主 agent 协调独立 Planner 制定方案，再派独立 Plan Reviewer 审查；两者有先后依赖 | 首审无阻断即交付合格 plan；有阻断时仅修订一次并复审受影响部分，仍阻断则如实返回 |
| code | 显式调用 `workflow-code-session`；协调 Coder、单目录、所有权、验证和本地提交 | 所有计划内改动已提交，固定 base/head、提交清单、验证和工作区状态可核验 |
| review | 使用 `local-pr-review` 固定范围五视角审查与汇总 | 分开报告执行完整性和阻断问题；只读且不自行修复 |

phase 内可处理不改变已批准语义的局部问题。关键前提失效、范围变化、共享目录脏改动、其他写者或提交失败时停止受影响工作并交主控；不得自动清理、stash、重设计、启动 Review 或修复闭环。

每个 phase 返回共同五项摘要及任务、阶段、session、轮次、需求/plan 版本和结果状态。收到全局变更时先通知主控并暂停；主控更新需求版本，再判定哪些已有结果失效。非自动 Review 的修复由用户选定，自动修复必须符合已批准次数和范围，新 HEAD 不复用旧 Review 结果。
