# 会话控制与恢复

## 启动和交接

主控在启动前核对任务、轮次、需求/plan 版本、授权、配置、资料入口和上一阶段及其写者的停止状态。交接必须包含共同五项摘要；代码还须带目录、固定 base/head、提交和测试事实。创建 API 会立即执行时，初始 prompt 必须携带完整交接。

先在记录中写入 `starting_session`、轮次和已发指令；只有获得真实 session ID 并收到开始 ACK 后，才更新 `current_phase` 和 `current_session`。clientThreadId 不冒充已开始 session。启动失败或状态不明先查询实际状态，禁止重复创建或重发实现指令；旧轮次或旧版本的迟到结果一律不推进当前阶段。

复用旧 phase 时，主控必须派发新轮次、完整新摘要和当前需求/plan 版本，再等待新的开始 ACK；旧 session 不能凭历史状态继续推进。

## 探查、停止与重试

连续 10 分钟没有有效进展时探查当前 phase，而不重新派发任务。有效进展是可核对的资料、测试、代码、提交或明确阻断；仅回复“还在处理”不构成有效进展。`WAITING_USER` 和正常长测试不算卡死；阶段最长时间仍按启动时已确认的任务约束执行。回复应说明当前工作、最近有效进展、阻塞、子 agent/命令是否在运行及建议。

建议参数必须在启动时展示并经用户确认：探查回复等待 2 分钟后再查询一次、同一临时故障最多重试 1 次、自动修复复审最多 1 轮、自动重规划最多 1 次、无新证据重复尝试 2 次后等待用户；阶段最长时间按任务设置。Plan Review 首审有阻断才修订一次并复审，仍阻断即上报。更换 session、模型或主 agent 不重置相同问题的计数。

无回复、死循环或不健康执行时，先查询状态并请求停止受影响执行。停止和恢复前核对全部写者和在途命令；只有确认全部停止才能启动替代执行者。停止未确认即阻断，不能假设消息、archive 或 interrupt 已使执行全部结束。

## 恢复和 heartbeat

压缩、中断或恢复后，主控先核对真实 session、子 agent、命令、文件、工作区和提交，再复用仍一致的证据。不能只凭旧摘要重复运行，也不能维护第二份全局账本。

heartbeat 只能在运行时能力已核验、用户接受实际精度限制并明确授权后启用；它可唤醒空闲主控，不能证明严格 10 分钟 SLA 或失联 phase 的强制停止能力。临时或正式 heartbeat 不替代状态核对和停止确认。

用户取消、结束任务或拒绝修复时停止后续调度，保留未解决事项和当前证据；不能把停止写成质量通过。
