# Agent 分工与等级

在每次任务启动、方案输出和执行启动前展示本次实际分工；执行中新增 Agent、改变模型或强度时，先展示变化及原因再派发。短任务只有主 Agent 时也用一句话告知配置，不为凑角色创建子 Agent。仅输出方案时，未启动的实现 Agent 标记为“拟派发”，已执行的 Plan Reviewer 按实际状态展示，不启动实现。

## 用户可见清单

| Agent ID | 角色与具体任务 | 阶段、依赖及并发上限 | 模型 / 推理强度 | 配置来源、状态 |
| --- | --- | --- | --- | --- |
| coder-1 | 核心逻辑 | 实现阶段，依赖契约确认 | gpt-5.6-terra / high | Skill 实现角色默认，未派发 |
| coder-2 | 独立测试 | 与 coder-1 并行 | sol / high | 用户指定，未派发 |

显示稳定 ID、实际计划人数和并行批次；规划、架构、编排可由同一个主 Agent 承担，不能计为三个已启动人员。Plan Review 的人数和视角由本 Skill 的风险分级决定；代码 Review 的人数、视角和汇总顺序由代码 Review Skill 决定；并发不足时分批，不减少必需视角。

每次清单附上：“你可以按角色或单个 Agent 修改模型与推理强度；未修改就按展示配置继续。”例如用户可以说“所有 coder 用 sol/high，coder-2 用 luna/medium，reviewer 用 astra/xhigh”。展示不新增逐 Agent 强制确认门；任务本身需要的方案、写入和 Git 授权仍独立生效。用户有新指令时在下一次派发前应用，不能用“默认继续”忽略已收到的修改。

## 解析与默认策略

- 模型和强度分别解析，优先级为：用户单个 Agent > 用户角色 > 用户任务默认 > Skill 角色默认 > 继承当前。只指定模型时，强度仍按此链路继承并检查兼容，不偷偷换成模型默认强度。
- 支持用户自然语言分配；将 `aster` 归一到 `astra`，`hight/xhight/mide/mid/med` 分别归一到 `high/xhigh/medium`。`astra/sol/luna` 及其他简称只能映射到当前派发后端能力中唯一且可用的精确模型 ID；多版本歧义、未知模型或不支持的组合先澄清，不能静默替换。不要固化随产品升级变化的模型清单。
- 核对的是当前原生派发工具或当前 CLI 的能力，不把 API、App 独立任务与子 Agent 的支持范围混为一谈。原生工具可直接继承但没有暴露具体值时写“继承当前（确切值未暴露）”；不得编造模型和等级。需要显式覆盖而无法验证能力时暂停该派发。
- Skill 角色默认：按 Plan 执行实现与修复的 Agent 使用 `gpt-5.6-terra / high`，派发时显式传入模型和强度，不自动降级。Planner/架构角色默认继承；独立 Plan Reviewer 默认继承当前模型、使用 `high` 推理强度，用户覆盖优先，代码 Reviewer/汇总者沿用其 Review Skill 配置。目标组合不可用或无法核实时暂停相关派发并说明原因，不静默替换。其他简单低风险辅助任务可在不覆盖用户显式字段的前提下透明降级，提前展示理由和验证要求。
- 自动降级任务验证失败时保留失败证据，可告知后使用原继承配置重试；不得靠更换模型把失败结果改成通过。权限、范围或能力错误不能通过降级绕过。
- 主 Agent 的当前模型不能用子 Agent 配置自行切换。用户指定独立 planner/architect 时，可在有并行价值且授权允许的情况下派发；若指定的是当前主 Agent 本身，说明需用户切换会话设置，不能假装已生效。
- 遵守派发工具的上下文限制：例如全量历史 fork 不接受模型覆盖时，用允许的有限历史或独立上下文，并交接目标、范围、约束、相关证据和完成标准。不要为了切换模型创建新的用户任务。

## 唯一状态与恢复

普通长任务在既有活动计划中保存 `agent_policy` 和 `agent_roster`；并行任务改由编排器的唯一外部账本保存，规划清单只保留初始分工和运行态定位。短任务可只在对话中展示，不强制落盘；不得修改全局 Codex 配置。

`agent_policy` 使用 `{schema_version:1,revision,defaults,roles,agents}`；后三项是配置映射，profile 只包含可选的 `model/effort`。Skill 默认按字段在用户配置之后解析，将有效实现/修复配置记录到对应角色或具体 Agent，保留逐字段来源；不要把 terra/high 写进全任务 `defaults`，以免传播给 Planner 或 Reviewer。自然语言中的“所有 reviewer”展开为角色配置，具体名称先映射到展示过的稳定 ID；不要把通配选择器原样留给不支持它的脚本。

`agent_roster` 保留配置 revision、已展示 revision、稳定 Agent ID、角色、任务、依赖/批次、用户原始指令及来源、解析后的模型/强度和逐字段来源。记录实际派发的工具 Agent ID、参数、证据来源、状态及每次 attempt；未派发、已派发和已完成分开。原生继承值未暴露时保留 null 和继承依据，不能把建议配置写成实际执行证据。

修改模型/强度仅递增配置 revision、告知用户并作用于后续派发；不重写运行中或已完成 attempt 的身份，不自动失效既有代码或方案。若用户要求以新配置重做 Review，则重跑受影响视角和汇总，旧结果保留为历史。职责、所有权、依赖或范围变化仍走原有方案/编排变更门禁。

恢复时先核对当前任务、配置 revision、已展示配置和真实 Agent 状态；不能把旧清单当成仍在运行，也不能用新配置覆盖历史执行记录。再次展示当前分工和可修改提醒后继续。所有本地 `.ai` 配置和任务记录仍不得进入最终 PR 提交。
