# 长任务执行与恢复

## 适用与权威来源

用户已经授权实施，且任务具有多个里程碑、大量独立事项、跨会话或明显上下文增长时使用。先复用项目既有方案和状态格式；等价状态无需另建文件。无既有约定时使用本地 `.ai/<task-id>/plan.md`。写入、检查点更新和 Git 检查沿用项目授权边界，缺少授权时记录待执行动作，不把口头摘要算作已持久化。

普通执行的活动计划保存全部任务事实；多 Agent/worktree 执行由 `parallel-feature-workflow` 的外部账本独占运行态。不得在不可变规划提交中回写进度，也不得让实现 Agent 与编排器同时写同一账本。

计划分为稳定的目标、原始需求、AC、范围、设计与验证要求，以及可变的当前状态、执行清单、证据、决策和偏离。计划描述意图与记录，实际文件和证据用于核对事实；冲突时停止受影响执行，不能简单选择其中一方。

## 执行循环

每次启动或恢复执行先按 [agent-roster.md](agent-roster.md) 展示当前分工、模型/强度和可修改提醒。`agent_policy/agent_roster` 复用本计划的唯一运行态；模型调整仅影响后续派发，不能覆盖历史 attempt，也不等于方案或源码变化。

1. 开始时读取原始目标、已确认方案和当前状态。多事项任务逐项建立 `REQ → AC → STEP/TASK → 实现 → TEST/证据`，与原始清单对照，不能从已完成文件反推应做事项。
2. 在已知里程碑内按局部上下文工作。步骤状态使用 `NOT_STARTED → IN_PROGRESS → IMPLEMENTED → VALIDATED → VERIFIED`；`BLOCKED` 记录阻塞原因及恢复条件。代码写完只支持 `IMPLEMENTED`，规定验证通过才支持 `VALIDATED`，独立反向验收后才支持 `VERIFIED`。
3. 里程碑结束、重大决策、阻塞、交接或主动暂停时写检查点。保存 phase、milestone、status、last completed、remaining、blockers、一个具体 next action；验证失败也必须记录。每个 shell 命令或微小修改无需同步。
4. 进入主要阶段、发生恢复或开始最终核验时重新校准全局目标。大量工具输出只留下可复查的证据位置、摘要和结论，不把完整日志复制进计划。

逐项枚举独立事项，不使用“9/10 完成”替代完整清单。原始请求和附加需求必须可持久读取，保留修改依据；原始清单的完整性由初始化及最终的原文复核证明，程序不能从自然语言自动证明没有漏登记。

## 偏离与证据失效

使用 `DEC-*` 记录重要选择的原因、影响和来源。普通进度更新不改变 `plan_revision`。触及范围、架构、公共行为、数据、安全、兼容、验收或回滚时，暂停受影响步骤，按主 Skill 形成并确认新版本；原要求与旧决定仍可追溯。更新完成条件不能用来掩盖遗漏。

实现或相关依赖、夹具、环境变化时，重新判断受影响测试和最终验收的有效性；无法证明可复用则降回 `IMPLEMENTED` 或阻塞。每条测试记录确切操作、预期、实际结果、实现快照与持久证据。没有执行、执行失败、证据丢失与结果未知均不能填为通过。

## 恢复

发生上下文压缩、跨会话恢复、记忆不完整或进度不确定时：

1. 暂停实施，定位任务 plan；并行任务通过本地 `.ai/resume.json` 或明确交接的定位文件找到外部账本。
2. 重读原始目标、AC、方案 revision、当前状态、关键决策和授权边界。
3. 在授权范围内检查 Git status（包括 untracked）、相关 diff、实际文件、已执行验证和证据快照。定位到账本或校验摘要通过并不等于源码仍有效。
4. 列出可复用产物、未完成项、失效证据和冲突。意图冲突需重新决策；事实记录落后时依据可核查产物修正，不能根据旧对话补造测试结果。
5. 更新检查点并留下具体下一动作后继续。找不到资料、尚有写者或权限不明确时保持阻塞。Git 操作未授权时可先做文件检查，但不能宣称 Git 恢复已完成。

多会话资料使用持久目录；同机可发现不代表克隆仓库后可恢复。跨机器需同步完整账本、原始请求和证据，验证身份及摘要后重绑定定位入口。

## 独立最终核验

实施结束后单独执行：重读原始目标与请求 → 对照完整 REQ/AC 清单 → 定位每项实现 → 检查对应测试及当前证据 → 检查最终差异和范围偏离 → 更新逐项核验结论。可由当前 Agent 在独立阶段执行；需要正式代码 Review 时交由既有 Review Skill，不自动要求额外 Agent。

只有全部必需事项已核验、无未解决偏离或阻塞，才能将任务置 `COMPLETE`。保留不适用的理由；不允许将未验证或用户未批准的删减变成成功。交付分支整理后须针对实际交付快照重新验证，开发 SHA 的证据不能直接继承。

复杂普通任务按 [plan-template.md](plan-template.md) 的唯一 `execution-state` 区块机械校验：

```bash
python3 <skill-dir>/scripts/validate_execution.py <plan.md> --root <project-root>
python3 <skill-dir>/scripts/validate_execution.py <plan.md> --root <project-root> --complete
```

脚本只读，不执行测试或 Git，不更新计划。它检查原始资料摘要、清单覆盖、状态、当前文件快照、删除项和证据；校验通过不能替代对需求语义、测试充分性或原始清单完整性的独立复核。它不解析任意项目已有格式，已有等价格式按同样不变量检查，不为了运行脚本强制重建状态。
