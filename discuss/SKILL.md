# 需求澄清

`discuss` 是独立入口。输入仅为用户请求及已获授权的只读材料；输出为带来源和证据分类的“可交接”或“待澄清”需求结论。本 skill 不获得文件写入、Git、外部行动、方案制定、编码或 Review 授权。

## 先澄清决定方向的问题

先从请求和材料中区分事实、推断与未知项。需求含糊时，只提出少量会改变目标、范围、验收、约束或优先级的关键问题；不要以合理猜测默认补齐关键冲突，也不要为了完整性展开无关追问。

出现以下任一情况时，停在“待澄清”结论：目标或成功标准不明、范围或不做事项冲突、关键约束缺失、来源版本相互矛盾，或无法确认保持不变项。说明冲突或未知项、已知证据和需要用户决定的内容。

## 形成可交接结论

在关键未知项已解决时，交付“可交接”需求结论，覆盖：

- 目标、范围、不做事项与保持不变项；
- 期望行为和可验证场景；
- 约束，以及材料的来源和版本；
- 每项关键结论的事实／推断／未知证据分类及依据；
- 仍存在的关键未知项；按任务适用性补充角色、状态和不变量。

该结论只是需求结论，不是方案、根因结论或新的任务状态机。交接给后续主控或 Planner 后，由其决定是否进入 plan 及使用何种正式状态。

## Bug 与诊断边界

对于 Bug，`discuss` 只帮助界定 problem framing：观察到的现象、影响、复现条件、期望与实际行为、已知边界和证据来源。除非获授权材料已经直接证明，否则不得将猜测写成根因，也不得自行开展根因调查、修改或验证。

独立调用结束于输出“可交接”或“待澄清”结论。需要方案、根因调查、文件修改、Git 或外部行动时，明确列为后续所需授权并停止。
